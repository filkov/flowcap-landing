# Flow Capture landing — handoff for another computer

## Start here

Repository: `https://github.com/filkov/flowcap-landing` (public). The `main`
branch publishes the root directory to GitHub Pages at `https://flowcap.me/`;
HTTPS is enabled. Open the repository as a project in Codex after cloning:

```sh
git clone https://github.com/filkov/flowcap-landing.git
cd flowcap-landing
python3 -m http.server 8793
```

Open `http://localhost:8793/` to preview. The site is plain HTML, CSS and
JavaScript with no package installation or build step. To publish an approved
change, commit and push to `main`, then verify the GitHub Pages deployment and
the affected live routes. Use a branch and PR when a review is needed.

Suggested first Codex message on the other computer: “Open this repository,
read `AGENTS.md` and `Docs/HANDOFF_2026-10-15.md`, then continue the Flow Capture
landing work from the current `main`. Check the live site and Figma artwork
before changing the design.”

## Current product and design state

- The homepage uses the forest/lake backdrop, the real transparent phone,
  voice-led copy, selective blue-to-violet gradient headings, and the Figma
  campaign artwork. Full-width map and voice cards include their text, followed by two smaller library and version cards. Card gaps are uniform; the desktop section title is one line, with no Library & Versions group label or chapter dividers. Isolated approved Figma layers are in `assets/product/`; their node IDs are documented in README.md.
- Feature close-ups show the actual map cards, cropped phone header, a readable HTML quote of the approved linked comment, native library app tiles and overlapping flow versions. The phone, comment and voice signal occupy separate non-overlapping areas. Map and voice cards include concise icon-led benefits with mint/violet accents.
- Handoff: accessible Claude & Codex / Figma / ZIP tabs explain the current export paths, alongside real screen previews. Three buttons select example AI requests; they do not send data or run an AI session. Product illustrations are noninteractive figures; circular enlargement arrows and the image dialog have been removed.
- Motion: short one-time entrances and one pass along the real map connection. Library tiles and handoff previews stay still. The voice waveform sits in its own empty area and alternates a restrained phrase with a long rest; it stops offscreen or in hidden tabs. Reduced motion and save-data retain static content. Hero camera and final phone position are preserved. At the owner’s request, the lake loop also gently varies the brightness of existing shore lights and their reflections, with no added lights or beams.
- Privacy heading and introduction are each one line on desktop; mobile wraps naturally. The closing block contains a single centered App Store badge.
- Header: transparent and full-width; only internal page links for MCP Setup
  and Guides. Footer: Guides, MCP Setup, Support, Privacy Policy, Terms of Use.
- The main hero action is Apple's App Store badge, linked to app ID 6811913058.
  The listing may remain unavailable until the app is published; do not claim
  the app can already be downloaded.
- `/mcp/` documents the public 0.3.3 Mac preview for Claude Desktop and Codex.
  The bundled downloads and checksums are versioned in `mcp/downloads/`.
  The browser OAuth path at `/connect/` is restricted preview and is not the
  public setup route. Neither a directory listing nor Windows support is live.
- `support@flowcap.me` is published in Support, Privacy and MCP Setup. Google
  Workspace inbox and self-delivery were verified on 14 October; external
  provider delivery and spam placement were not independently tested.

## Checks before pushing

```sh
node --check landing.js
node --check mcp/mcp.js
node --check connect/connect.js
git diff --check
```

Also check every changed local image, stylesheet, script and page link; review
the changed routes in a browser at desktop and mobile widths. Keep secrets and
local test data out of Git. GitHub Pages deploys from `main`; a successful Git
push is not by itself proof that the live page has refreshed.
